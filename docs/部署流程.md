## 2. 服务器准备

### 2.1 选购
- 阿里云 ECS，2核2G 即可（轻量练手 ¥284/年）
- 系统镜像：Alibaba Cloud Linux 3（或 CentOS 7.9）

### 2.2 公网 IP
- 新购实例默认可能只有内网 IP（如 172.19.x.x）
- 控制台 → 实例 → 更多 → 网络和安全组 → **调整公网带宽**（1M 起步）→ 分配公网 IP

### 2.3 安全组（重要）
放行端口：**22**（SSH）、**80**（HTTP）、**443**（HTTPS）
**不要放行**：3306（MySQL）、8000（后端）——它们只允许本机访问，通过 Nginx 转发，避免数据库/后端直接暴露公网

### 2.4 SSH 登录
- 首次登录用密码：控制台 → 实例 → 重置实例密码 → 重启实例
- 连接工具：Xshell / FinalShell / 系统自带终端

```bash
ssh root@118.31.106.227
```

## 4. MySQL 8 安装与配置

### 4.1 安装
```bash
dnf install -y mysql-server
systemctl enable --now mysqld
```

### 4.2 首次进入（无密码模式）
```bash
mysql -u root
```

### 4.3 建库建用户（务必用不含 `@` 的密码！）
```sql
-- 设置 root 密码（可选）
ALTER USER 'root'@'localhost' IDENTIFIED BY 'Root@2026abc';
FLUSH PRIVILEGES;

-- 建业务库（utf8mb4）
CREATE DATABASE IF NOT EXISTS opsagent DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 建业务账号（密码不要含 @，会破坏连接串）
CREATE USER 'opsagent'@'localhost' IDENTIFIED BY 'Ops2026abc!';
GRANT ALL PRIVILEGES ON opsagent.* TO 'opsagent'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

### 4.4 内存优化（2核2G 小机器必做）
```bash
vim /etc/my.cnf
```

追加：
```ini
[mysqld]
innodb_buffer_pool_size = 256M
performance_schema = OFF
```

重启生效：
```bash
systemctl restart mysqld
```

## 6. 后端部署

### 6.1 创建虚拟环境 + 安装依赖

```bash
cd /opt/opsagent
python3.11 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

> requirements.txt 内**不要有中文注释**（Windows 本地 pip 用 GBK 编码读取会报 UnicodeDecodeError）。

### 6.2 Chroma sqlite3 修复（关键！）

服务器系统 sqlite3 < 3.35，Chroma 无法启动，报错：
`RuntimeError: Your system has an unsupported version of sqlite3. Chroma requires sqlite3 >= 3.35.0.`

**一次性修复（当前代码未固化时手动执行）**：

```bash
source /opt/opsagent/.venv/bin/activate
pip install pysqlite3-binary
sed -i '1i import pysqlite3\nimport sys\nsys.modules["sqlite3"] = sys.modules.pop("pysqlite3")' /opt/opsagent/app/rag/service.py
# 验证
head -5 /opt/opsagent/app/rag/service.py
```

> ⚠️ **根治**：让 Trae 把上面 3 行 pysqlite3 代码写进 `app/rag/service.py` 顶部并提交到仓库，并在 requirements.txt 加 `pysqlite3-binary`。固化后每次更新代码不再丢失，无需手动执行本步。

### 6.3 配置 .env

**先检查服务器 .env 是否存在**（tar 解压不会删除已有文件，但如果打包时没排除 .env 会覆盖）：

```bash
ls -la /opt/opsagent/.env
```

不存在则从模板创建：

```bash
cp /opt/opsagent/.env.example /opt/opsagent/.env 2>/dev/null || vim /opt/opsagent/.env
```

**关键配置（按服务器实际情况）**：

```env
# ---- MySQL 8 ----
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=opsagent
MYSQL_PASSWORD=Ops2026abc!
MYSQL_DATABASE=opsagent

# ---- JWT ----
JWT_SECRET=OpsAgent2026SecretKeyForJwtTokenGenerationAtLeast32Chars
JWT_ALGORITHM=HS256
JWT_EXPIRE_DAYS=7

# ---- 阿里百炼（可留空，用户网页自配兜底）----
DASHSCOPE_API_KEY=
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
CHAT_MODEL=qwen-plus
BACKUP_CHAT_MODEL=qwen-flash
REASONING_MODEL=qwen-plus
EMBED_MODEL=text-embedding-v3
RERANK_MODEL=gte-rerank-v2

# ---- SQL 方言（锁定 Oracle）----
SQL_DIALECT=oracle

# ---- 服务配置（部署必须 0.0.0.0）----
HOST=0.0.0.0
PORT=8000

# ---- 会话与查询约束 ----

QUERY_MAX_ROUNDS=5
PASTE_MAX_LINES=30
```

**数据库变更执行**（管理员功能等新增表/字段，以 Trae 给出的 SQL 为准，示例）：

```sql

```

## 7. systemd 常驻服务

```bash
vim /etc/systemd/system/opsagent-backend.service
```

```ini
[Unit]
Description=OpsAgent Backend
After=network.target mysqld.service

[Service]
Type=simple
WorkingDirectory=/opt/opsagent
ExecStart=/opt/opsagent/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

```bash
chmod 644 /etc/systemd/system/opsagent-backend.service
systemctl daemon-reload
systemctl enable --now opsagent-backend

# 验证
systemctl status opsagent-backend --no-pager
curl http://127.0.0.1:8000/docs -m 5   # 返回 Swagger HTML 即成功
```

## 9. Nginx 配置

```bash
vim /etc/nginx/conf.d/opsagent.conf
```

```nginx
server {
    listen 80;
    server_name 118.31.106.227;

    # 前端静态文件
    location / {
        root /var/www/opsagent;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }

    # WebSocket（流式输出）
    location /ws/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 300s;
    }

    # 上传大小限制
    client_max_body_size 50M;
}
```

> ⚠️ **vim 粘贴丢字符坑**：粘贴后第一行可能变成 `erver {` 导致 `nginx -t` 报 `unknown directive "server"`。
> 检查：`head -1 /etc/nginx/conf.d/opsagent.conf`，若丢字：
> `sed -i '1s/^/s/' /etc/nginx/conf.d/opsagent.conf`

```bash
nginx -t                    # 必须 syntax is ok
systemctl enable --now nginx
systemctl restart nginx
```

## 12. 后续更新操作全流程

- **sqlite3 修复**：代码已固化则跳过；未固化则每次解压后需重新执行（见 6.2）

### 12.1 后端更新（代码变更）

### 12.3 数据库更新

让 Trae 在改代码时**同步输出本次数据库变更 SQL**，在服务器执行：


### 12.4 一键更新脚本（推荐）

服务器创建 `/opt/opsagent/update.sh`：

```bash
vim /opt/opsagent/update.sh
```

```bash
#!/bin/bash
# OpsAgent 后端一键更新
cd /opt
echo "=== 1. 解压代码（如 /opt 下已有 opsagent.tar.gz） ==="
if [ -f opsagent.tar.gz ]; then
  tar -xzf opsagent.tar.gz -C opsagent
  rm -f opsagent.tar.gz
  echo "解压完成"
fi

echo "=== 2. 确认 .env / data 未被覆盖 ==="
ls -la /opt/opsagent/.env
ls /opt/opsagent/data 2>/dev/null || mkdir -p /opt/opsagent/data

echo "=== 3. 更新依赖 ==="
source /opt/opsagent/.venv/bin/activate
pip install -r requirements.txt -q

echo "=== 4. sqlite3 修复检查（未固化时补丁） ==="
if ! grep -q "pysqlite3" /opt/opsagent/app/rag/service.py; then
  sed -i '1i import pysqlite3\nimport sys\nsys.modules["sqlite3"] = sys.modules.pop("pysqlite3")' /opt/opsagent/app/rag/service.py
  echo "已补 sqlite3 补丁"
else
  echo "已固化，跳过"
fi

echo "=== 5. 重启后端 ==="
systemctl restart opsagent-backend
sleep 5
systemctl status opsagent-backend --no-pager | head -6

echo "=== 完成 ==="
```

```bash
chmod +x /opt/opsagent/update.sh
```

以后后端更新三步：**本地打包上传 → 服务器 `bash /opt/opsagent/update.sh` → 浏览器验证**。

## 13. 踩坑记录表

| # | 现象 | 原因 | 解决 |
|---|------|------|------|
| 1 | 实例没有公网 IP | 新购默认仅内网 | 控制台调整带宽分配公网 IP |
| 2 | SSH Permission denied (publickey) | root 密码未设 | 控制台重置密码 + 重启实例 |
| 3 | 服务器装 Node 一直卡死 | 国内访问 nodesource 及各家镜像全部超时 | 放弃服务器装 Node，本地构建 dist 上传 |
| 4 | GitHub clone 超时 | 网络问题 | 浅克隆 + 放宽 lowSpeedLimit，或 Gitee/tar+scp |
| 5 | MySQL 连接报 `'2026abc@localhost'` | 密码含 `@` 破坏连接串 | 密码改不含 `@`（Ops2026abc!） |
| 6 | Chroma 报 sqlite3 >= 3.35.0 | 系统 sqlite 版本低 | pip install pysqlite3-binary + service.py 顶部替换（固化到代码） |
| 7 | Nginx `unknown directive "server"` | vim 粘贴首行丢字变 `erver` | `sed -i '1s/^/s/'` 补回，或改完 head -1 检查 |
| 8 | 2核2G MySQL 内存吃紧 | 默认配置过大 | innodb_buffer_pool_size=256M + performance_schema=OFF |
| 9 | Windows 本地 pip 装依赖报 UnicodeDecodeError | requirements.txt 有中文注释，GBK 读不了 | 删中文注释（纯 ASCII） |
| 10 | 更新代码后 502 / sqlite3 报错复现 | tar 覆盖把服务器手动打的 sqlite3 补丁覆盖掉 | 补丁固化进代码 + update.sh 自动检测补丁 |
| 11 | 更新后 Access denied for user 'root' | 打包没排除 .env，本地 root/123456 覆盖了服务器配置 | 打包加 --exclude=.env，服务器 .env 永不上传 |
| 12 | systemctl status 显示 `bad; vendor preset: disabled` | unit 文件权限问题 | chmod 644 + daemon-reload |
| 13 | 前端接口 502 | 前端写死 localhost:8000 | 改用相对路径 /api |
| 14 | 密码忘了 | bcrypt 单向加密无法解密 | 管理员重置 / 数据库改哈希（见问答） |

## 14. 安全建议

1. **安全组最小放行**：22 / 80 / 443，3306 与 8000 永不放行
2. **访问控制**（部署后选一种）：
   - A：安全组 IP 白名单（只允许自己/公司 IP 访问 80）
   - B：邀请码注册（推荐：代码加注册邀请码校验，管理员分发）
   - C：完全公开（当前状态，不推荐）
3. **定期备份**（至少备份 MySQL + data/chroma）：

```bash
# MySQL 备份
mysqldump -u opsagent -p opsagent > /opt/backup/opsagent_$(date +%F).sql

# Chroma 数据备份
tar -czf /opt/backup/chroma_$(date +%F).tar.gz /opt/opsagent/data
```

4. **API Key 安全**：服务器 .env 的 DASHSCOPE_API_KEY 可留空，由用户网页自配，避免明文存服务器
5. **HTTPS**（有条件时）：阿里云免费证书 + certbot，443 端口反代
